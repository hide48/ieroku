# 001 家電登録 — 仕様

- 状態: 承認済み（2026-11-28）
- 入力: [INTERVIEW.md](INTERVIEW.md)（claude.ai のヒアリング）＋ `/spec` の追加インタビュー
- 画面モック・データフロー・コード断片: [design.html](design.html)

## 1. 目的とスコープ

家電・住宅設備・家具を登録し、保証期限を管理して、期限前にメールで知らせる。実際に使い始められる最小限（MVP）。

- **含む**: 世帯・利用者の土台（Access JWT 検証）／部屋・種類・家族の管理／家電と保証（複数）の登録・編集・一覧・検索／処分済み・復元・完全削除／操作履歴／添付ファイル（写真・PDF）／保証期限のメール通知と受信設定
- **含まない**: AI 読み取り（0012、第 2 弾）／間取り図／Web プッシュ通知・PWA 化／世帯や利用者を画面から追加する機能（スクリプトで登録）／CSV 入出力／修理・点検の記録／PC 向けの画面構成（表形式の一覧・横並びの詳細など。後の機能で検討）／繰り返す予定の管理（防蟻処理の再施工・住宅の定期点検・早めの通知。002 で検討。001 でも種類「住宅」・保証「その他」として期限と通知は使える）

## 2. 用語

| 用語           | 意味                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 家電           | 登録する物すべて（家電・住宅設備・家具）。テーブル名は `items`                                                                          |
| 種類           | 家電の分類。世帯ごとに登録制。初期値「家電」「住宅設備」「家具」                                                                        |
| 部屋           | 設置場所。世帯ごとに登録制。初期値なし。任意（イヤホンなど持ち歩くものは未設定でよい）                                                  |
| 保証           | 1 件の家電に 0 件以上。メーカー保証・延長保証など。それぞれ期限と通知を持つ                                                             |
| 有効／期限切れ | 今日（JST）≦ 期限日なら有効、期限日 < 今日なら期限切れ                                                                                  |
| 処分済み       | 家電の状態。一覧から隠れ、通知が止まる。復元できる                                                                                      |
| 家族           | 世帯の人の一覧（`members`）。購入者に使う。ログインしない人（子どもなど）も登録できる。ログインできる人（`users`）は家族の 1 人に紐づく |
| 入手方法       | 「購入」か「もらいもの」。もらいものは購入日を「受け取った日」と表示し、贈り主を呼び名で書ける                                          |

## 3. データモデル（D1）

ID はすべて `crypto.randomUUID()` の文字列。日付は `YYYY-MM-DD` の文字列（JST の暦日）、日時は UTC の ISO 文字列。**全テーブルに `household_id`（NOT NULL）**を持ち、子テーブルも親と同じ世帯 ID を重ねて持つ。

| テーブル                  | 項目（型・必須・制約）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `households`              | `id`, `created_at`（世帯名は持たない＝苗字を保存しない）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `users`                   | `id`, `household_id`, `email`（必須・全体で一意・小文字化）, `notify_email`（bool, 既定 true）, `created_at`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `members`                 | `id`, `household_id`, `name`（必須, 1〜20 字, 前後空白除去, 世帯内で一意）, `user_id`（任意, FK, 一意。ログインできる人のみ）, `sort_order`（int）, `created_at`, `updated_at`。表示名はここで持つ                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `rooms` / `categories`    | `id`, `household_id`, `name`（必須, 1〜30 字, 前後空白除去, 世帯内で一意）, `sort_order`（int）, `created_at`, `updated_at`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `items`                   | `id`, `household_id`, `name`（必須, 1〜100 字）, `category_id`（必須, FK）, `room_id`（任意, FK）, `maker`（任意, ≤100）, `model_number`（任意, ≤100）, `acquisition`（必須, `purchased`/`gift`, 既定 `purchased`）, `purchased_on`（必須。もらいものは受け取った日）, `purchased_by_member_id`（任意, FK, 購入のときのみ）, `store`（任意, ≤100, 購入のときのみ）, `price_yen`（任意, 整数 0〜100,000,000, 購入のときのみ）, `gift_from`（任意, ≤30, もらいもののときのみ）, `note`（任意, ≤1000）, `status`（`active`/`disposed`）, `disposed_on`（処分時のみ）, `created_by`, `created_at`, `updated_by`, `updated_at` |
| `warranties`              | `id`, `household_id`, `item_id`（FK, 家電の完全削除で連鎖削除）, `kind`（`maker`/`extended`/`other`）, `provider`（任意, ≤100）, `starts_on`（必須, 初期値=購入日）, `months`（任意, 1〜240）, `expires_on`（必須）, `expires_on_manual`（bool）, `created_at`, `updated_at`                                                                                                                                                                                                                                                                                                                                              |
| `attachments`             | `id`（= R2 キーの UUID 部分）, `household_id`, `item_id`（FK）, `content_type`（`image/jpeg`/`application/pdf`）, `size_bytes`（≤25MB）, `original_name`（DB のみ。パス・URL・ログには使わない）, `created_by`, `created_at`                                                                                                                                                                                                                                                                                                                                                                                              |
| `item_events`             | `id`, `household_id`, `item_id`（FK, 連鎖削除）, `actor_user_id`, `action`（`created`/`updated`/`disposed`/`restored`/`attachment_added`/`attachment_removed`）, `at`。**変更前後の値は持たない**                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `notification_deliveries` | `id`, `household_id`, `warranty_id`（FK, 連鎖削除）, `user_id`, `stage`（`d30`/`d7`）, `expires_on`（送った時点の期限日）, `status`（`sent`/`failed`）, `attempts`, `last_attempt_at`。一意: (`warranty_id`, `user_id`, `stage`, `expires_on`)                                                                                                                                                                                                                                                                                                                                                                            |

- R2 キーは `{household_id}/{attachments.id}`。マイグレーションは追加のみで、戻すときは新しいマイグレーションで行う
- ログインできる人を増やす（家族にログインさせる）のは 001 の対象外。Access の許可メール（Terraform）と `users` の追加が必要
- AI 解析（0012）の出力形は `ItemDraft`（`name, maker, model_number, purchased_on, store, price_yen, warranties[{kind, provider, starts_on, months, expires_on}]`）とし、登録フォームの Zod スキーマと同じものを使う

## 4. 画面と操作（スマホ幅 360〜430px を基準）

下部に「一覧」「登録」「設定」のタブ。モックは design.html。PC では同じ 1 列の画面を最大幅 640px で中央寄せにして表示する（PC 専用の画面は作らない）。添付はファイル選択ボタンで PC からも追加できる。

1. **一覧** `/items` … 検索欄（品名・メーカー・型番の部分一致）、並べ替え「期限が近い順（既定）／部屋ごと／種類ごと」。各行に品名・種類・部屋・最も近い保証のバッジ。末尾に「処分済みを見る」
2. **登録** `/items/new` … 品名・種類（選択）・部屋（選択・未設定可）・メーカー・型番・入手方法（購入／もらいもの）・購入日・購入者（家族から選択・未設定可）・購入店・金額・メモ。もらいものを選ぶと、購入日の見出しが「受け取った日」になり、購入者・購入店・金額の代わりに「贈り主（呼び名）」が出る。「保証」欄は既定で 1 件（メーカー保証）。「＋保証を追加」で増やす。「保証なし」を選ぶと保証欄を消す
   - 保証ごとに 種別・提供者・開始日（=購入日）・期間（月。選択肢: 6/12/24/36/60/120 と自由入力）・期限日。期限日は自動計算し、手で直すと「手入力」表示になり以後自動で上書きしない（「自動計算に戻す」で解除）
3. **詳細** `/items/$id` … 全項目・保証の一覧（残り日数）・添付ファイル（サムネイル／PDF アイコン、タップで表示）・操作履歴（「○○さんが 11/28 に編集」）。操作: 編集／処分済みにする（処分日を入力、既定は今日）
4. **編集** `/items/$id/edit` … 登録と同じフォーム。保証の削除もここで行う
5. **処分済み一覧** `/items/disposed` … 処分日の新しい順。詳細画面から「元に戻す」「完全に削除」（確認ダイアログで品名を表示）
6. **設定** `/settings` … 部屋・種類・家族の管理（追加・名前変更・上下ボタンで並べ替え・削除）、自分の「通知メールを受け取る」スイッチ。自分の表示名は家族の一覧で変える

## 5. 業務ルール

- **期限の計算**: `expires_on = addMonths(starts_on, months) − 1 日`。月末は丸める（1/31 + 1 か月 → 2/28 → 前日 2/27。2024-02-29 + 12 か月 → 2025-02-28 → 2/27）。計算は `src/lib/warranty.ts` の純関数 1 か所のみ。日付の計算・「今日（JST）」の取得は `temporal-polyfill` の `Temporal.PlainDate` を明示的に import して使い（`src/lib/date.ts` にまとめる）、`Date` は使わない。ブラウザ組み込みの Temporal には頼らない（iOS Safari・Workers が未対応のため）
- 保証ありの場合、各保証の `expires_on` は必須で `starts_on` 以上。購入日は今日以前（未来日は不可）
- **一覧の並び（期限が近い順）**: 有効な保証の最も近い期限の昇順 → 期限切れのみの家電（最も新しい期限の降順）→ 保証なし（品名順）
- **バッジ**: 有効かつ残り 30 日以内=注意色「あと N 日」／有効=「〜YYYY/MM/DD」／期限切れ=灰色「期限切れ」／保証なし=「保証なし」
- **部屋・種類の削除**: 紐づく家電（処分済みを含む）が 1 件でもあれば削除不可。「この部屋に N 件の家電があります」と表示
- **家族の削除**: 購入者として使われている家族と、ログインできる人に紐づく家族は削除不可。初期値は世帯登録スクリプトで 2 人分を作る
- **入手方法**: `gift` のときは `purchased_by_member_id`・`store`・`price_yen` を、`purchased` のときは `gift_from` を、サーバー側で null にして保存する（切り替えて保存すると片方は消える）
- **重複**: 家電の重複は禁止しない（同じ型番を 2 台持てる）。部屋・種類・家族の名前は世帯内で重複不可
- **状態遷移**: `active` →（処分）→ `disposed` →（元に戻す）→ `active`。`disposed` からのみ完全削除（DB の行と R2 のファイルを消す。R2 削除に失敗しても DB は消し、孤立ファイルは週 1 回の Cron で掃除）
- **履歴**: 登録・編集・処分・復元・添付の追加/削除で `item_events` に 1 行。完全削除時は履歴も消える
- **添付**: 1 家電 10 ファイルまで、1 ファイル 25MB まで（写真は作り直した後の大きさで判定）。画像はクライアントで JPEG（長辺 4000px を超えるときだけ縮小, 品質 0.85）に再エンコードして EXIF を除去。PDF はそのまま送る。アップロード・閲覧とも Worker で全体をメモリに読み込まず、ストリームのまま R2 と受け渡す（Worker のメモリは 128MB）。サーバーで先頭バイト（JPEG `FF D8 FF`／PDF `%PDF-`）とサイズを検証
- **通知**: Cron `0 23 * * *`（UTC＝毎朝 8:00 JST）。今日を D（JST）として、`active` の家電の保証のうち `expires_on − 30 = D`（d30）または `expires_on − 7 = D`（d7）のものを、`notify_email = true` の利用者ごとに **1 通にまとめて**送る
  - 段階の日が保証の登録日（JST）より前なら送らない（通り過ぎた分は送らない）
  - 送信に失敗したら `failed` を記録し、翌日・翌々日に再送（最大 3 回）。`sent` の組は二度と送らない。期限日を直すと新しい期限で再び対象になる
  - 本文: 品名・保証の種別・期限日・詳細画面へのリンクのみ。金額・購入店・部屋・添付・メーカー/型番は書かない。件名は「保証期限のお知らせ（N 件）」

## 6. セキュリティ・個人情報

- 世帯 ID は Access JWT → `users.email` → `household_id` で決め、入力からは受け取らない。JWT がない・不正・未登録のメールは 403（本文に理由やメールを出さない）
- `src/server/data/` の関数は第 1 引数に `HouseholdScope`（世帯 ID を持つ型）を取り、全クエリの WHERE に入れる。FK の参照先（部屋・種類・家族・家電）も同じ世帯かを確認する
- 添付の閲覧は `/api/files/$id?exp=&sig=`（60 秒の HMAC 署名付き URL）。Worker が署名・期限・Access JWT・世帯を検証してから R2 から返す（`Cache-Control: private, no-store`、`Content-Disposition` に元ファイル名を使わない）
- ログには ID・件数・エラー種別のみ。品名・金額・メール・ファイル名・家族の名前・贈り主は出さない。通知 Cron のログも件数のみ
- 通知メールの宛先は `users` に登録した 2 アドレスのみ（send_email の許可宛先でも制限）
- `DEV_AUTH_EMAIL` は `APP_ENV=production` で設定されていたら起動停止（テスト付き）
- 他の世帯のデータを読み書きできないテストを、全データアクセス関数・全サーバー関数・ファイル配信に付ける（世帯 A・B を作り、B の ID で A を指定して 404 になる）

## 7. 受け入れ条件（E2E: スマホ幅の Chromium と WebKit。1・5・7 は PC 幅 1280px の Chromium でも確認）

1. 品名「冷蔵庫」・種類「家電」・購入日 2026-04-01・メーカー保証 12 か月で登録すると、一覧に「冷蔵庫」と「〜2027/03/31」が表示される
2. 開始日 2024-02-29・12 か月にすると、期限日欄に 2025-02-27 が入る。期限日を手で 2025-03-31 に直して保存すると、詳細に「2025/03/31（手入力）」が表示される
3. 型番・メーカー・部屋を空のまま登録できる。品名・種類・購入日のどれかが空だと、その欄の下にエラーが表示され保存されない
4. 保証を 2 件（メーカー・延長）付けて登録すると、詳細に 2 件が別々の期限で表示される。「保証なし」で登録すると一覧に「保証なし」が表示される
5. 期限が 20 日後・200 日後・昨日の家電があるとき、期限が近い順の一覧はこの順で並び、それぞれ「あと 20 日」（注意色）・日付・「期限切れ」（灰色）が表示される
6. 検索欄に型番の一部を入れると、その家電だけが表示される。「部屋ごと」にすると部屋名の見出しの下にまとまり、部屋なしは「未設定」に入る
7. 処分済みにすると一覧から消え、処分済み一覧に表示される。「元に戻す」と一覧に戻る。処分済みから「完全に削除」すると、どちらの一覧にも表示されない
8. 家電が 1 件ある部屋を削除しようとすると「この部屋に 1 件の家電があります」と表示され、部屋は残る。家電のない部屋は削除できる
9. 写真を添付すると詳細にサムネイルが表示され、保存された JPEG に EXIF の GPS 情報がない。長辺 6000px の写真は長辺 4000px で保存される。11 件目の追加、25MB 超の PDF、PNG を JPEG と偽ったファイルはエラーになる
10. 添付の URL を 61 秒後に開くと 403 になる。別の世帯の利用者で同じ URL を開くと 404 になる
11. 詳細画面の履歴に「（表示名）さんが登録」「（表示名）さんが編集」が新しい順に表示される
12. 期限 30 日前の保証がある日に通知処理を実行すると、受信オンの利用者に 1 通だけ送られる（ローカルの送信記録で確認）。同じ日に 2 回実行しても 2 通目は送られない。受信オフの利用者と処分済みの家電には送られない
13. 別の世帯の家電 ID を URL に入れて詳細を開くと「見つかりません」が表示される
14. PC 幅（1280px）で一覧・登録・詳細を開くと、内容が中央の 1 列に収まり、横スクロールが出ない
15. 入手方法を「もらいもの」にすると、購入日の見出しが「受け取った日」に変わり、購入者・購入店・金額が消えて「贈り主」が出る。贈り主「実家」で保存すると詳細に「もらいもの（実家）」が表示される
16. 設定で家族「こども」を追加すると、登録画面の購入者の選択肢に出る。購入者として使われている家族を削除しようとすると「この家族が購入者の家電が N 件あります」と表示され、削除されない

## 8. 実装の分割（PR 単位）

1. **土台**: 環境変数の Zod 検証、Access JWT 検証、`DEV_AUTH_EMAIL`、`households`/`users`、`HouseholdScope`、世帯登録スクリプト、`pnpm test`・`pnpm e2e` の整備、D1 バインディング

4. **一覧・検索・処分・復元・完全削除**

6. **通知**: Cron、send_email、配信記録、受信設定
