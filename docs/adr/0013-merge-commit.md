# 0013 PR のマージはマージコミットにする

- 状態: 承認済み（2026-11-27）
- 置き換え: 0010 の「マージは squash のみ」の部分のみ。0010 のそれ以外の決定は有効のまま

## 背景

0010 では、PR のマージを squash のみとしていた。しかし PR #1 のように、1 つの PR を意味のまとまりごとのコミット（docs と chore など）に分けることがある。squash ではこの区切りが 1 つにまとまって失われる。PR 内のコミットを main の履歴に残したい。

## 決定

- PR のマージは**マージコミット**（Create a merge commit）にする。squash と rebase によるマージは GitHub の設定で無効にする
- main の保護ルールで「直線的な履歴を必須にする（Require linear history）」は有効にしない
- PR 内のコミットはそのまま main に残るため、次を守る
  - 1 コミット = 1 つの意味のまとまり。Conventional Commits（種別は英語、本文は日本語）で書く
  - 「レビュー指摘の修正」「タイポ修正」のような途中経過のコミットは、マージ前に該当するコミットへまとめる（`git commit --fixup` と `git rebase --autosquash`）
  - まとめ直しはできるだけ push の前に行う。push 後にまとめ直した場合の force push（`--force-with-lease`）は PR のブランチに限り、ひでが行う（Claude の force push は 0006・0010 のとおり禁止のまま）
- マージ後のブランチの自動削除は 0010 のとおり有効にする

## 検討した代替案

- squash のみ（0010 の元の決定）: main の履歴は 1 PR = 1 コミットで簡潔だが、PR 内のコミットの区切りが失われる
- rebase マージ: コミットは残るが、どの PR で入った変更かが履歴から分からなくなり、PR 単位で戻しにくい

## 影響

- main の履歴にマージコミットが入り、履歴がやや複雑になる（`git log --first-parent` で PR 単位に見られる）
- PR 単位で戻すときはマージコミットを `git revert -m 1` で取り消す
- コミットを整える手間が増える。Claude は対話的な rebase を使えないため、`--fixup` と `--autosquash` で整理する

## 見直す条件

- 途中経過のコミットが main に残ることが続き、履歴が読みにくくなった
