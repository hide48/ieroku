# 0016 添付ファイルは Worker が検証して返す署名付き URL で配信する

- 状態: 提案（2026-11-28）

## 背景

保証書・レシートの写真や PDF を R2 の非公開バケットに置き、閲覧は 60 秒の署名付き URL のみとするルールがある。R2 の S3 互換 API の署名付き URL を使うと、R2 のアクセスキーを Worker の秘密に置く必要があり、URL が漏れると 60 秒間は Access を通らずに誰でも取得できる。

## 決定

- 閲覧 URL は `/api/files/{添付ID}?exp={期限}&sig={HMAC}` とし、アプリの Worker が配信する
- Worker は HMAC（秘密は `wrangler secret`）・期限（発行から 60 秒）・Access JWT・利用者の世帯と添付の世帯の一致をすべて確認してから、R2 バインディングで取得して返す
- 応答は `Cache-Control: private, no-store`。`Content-Disposition` に元のファイル名を使わない
- R2 の S3 API 用アクセスキーは発行しない

## 検討した代替案

- R2 の S3 互換の署名付き URL: Worker を通らないため負荷は小さいが、アクセスキーの管理が増え、URL だけで取得できる
- 公開バケット + 推測できないキー: ルール違反

## 影響

- ファイルの転送が Worker を通る。1 ファイル 25MB 以下・2 人の利用で、R2 との受け渡しはストリームのまま行う（メモリ 128MB・リクエスト 100MB の制限に当たらない）。ストリームの転送は CPU 時間をほとんど使わない
- HMAC の秘密を本番に追加する必要がある

## 見直す条件

- Worker の CPU・転送量の制限に当たる
