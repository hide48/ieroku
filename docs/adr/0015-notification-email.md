# 0015 通知メールの送り方と、メールに書いてよい情報

- 状態: 提案（2026-11-28）

## 背景

保証期限の通知（001）をメールで送る。メールはアプリの外（メールサーバー・端末の通知・バックアップ）に残り、Access でも守れない。送信手段の追加は外部への出口を増やす。

## 決定

- 送信は Cloudflare の `send_email` バインディングを使い、宛先は `users` に登録した世帯の 2 アドレスに限定する（バインディングの許可宛先でも制限する）
- Cron Triggers で毎朝 8:00 JST に 1 回だけ確認し、利用者ごとに 1 通にまとめる
- 本文に書いてよいのは **品名・保証の種別・期限日・詳細画面へのリンク** だけ。金額・購入店・部屋・メーカー/型番・添付ファイル・住所は書かない
- 送信の記録（保証・利用者・段階・期限日）を D1 に残し、同じ通知を二重に送らない。失敗時の再送は最大 3 日
- 送信のログは件数とエラー種別のみ

## 検討した代替案

- Resend などの外部メール API: API キーの管理と、データの渡し先が増える
- Web プッシュ通知: iPhone は PWA のインストールが必要。後で追加を検討する
- 件数とリンクだけのメール: 最も安全だが、開かないと内容が分からず通知の意味が薄い

## 影響

- 送信元に独自ドメイン（0011）と Email Routing の設定が必要
- 品名はメールに残る。品名に個人情報を書かない運用を前提にする

## 見直す条件

- 送信先を世帯外に広げる、または送信量が Cloudflare の制限を超える
