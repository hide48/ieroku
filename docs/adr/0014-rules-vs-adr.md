# 0014 今のルールは CLAUDE.md と `.claude/rules/`、ADR は判断の記録

- 状態: 提案（2026-11-27）
- 置き換え: 0009 の「優先順位は ADR → CLAUDE.md → ガイド」の部分のみ

## 背景

ADR を今のルールとして参照していたため、次の問題が出た。

- 判断を 1 つ変えるたびに、新しい ADR・旧 ADR への注記・CLAUDE.md の修正が必要になり、今のルールを知るには複数の ADR を読む必要があった（0010 と 0013 の例）
- 0009 の優先順位が、過去の記録を今のルールより上に置いていた
- CLAUDE.md に ADR の一覧やフォルダごとの詳細を書いていたため、ADR が増えるほど毎回読み込まれる量が増える

Claude Code の公式ドキュメント（メモリーのページ）は、CLAUDE.md は 1 ファイル 200 行以内を目安にし、毎回必要なことだけを書き、フォルダ固有のルールは `.claude/rules/` に `paths:` 付きで分けるよう勧めている。

## 決定

- 今のルールの正本は CLAUDE.md と `.claude/rules/`。ADR はルールの参照先にせず、「なぜ」の記録として扱う
- ルールと ADR が食い違っていたら、どちらかを優先せずに不備として報告する
- ADR はアーキテクチャ・安全性に関わる判断のときだけ書く。運用の細部は CLAUDE.md を直す
- ADR の本文は書き換えない。後の変更は `docs/adr/README.md`（目次）の「その後」に書く
- CLAUDE.md には全体に効くルールだけを書く。特に重要なもの（DB アクセスは `src/server/data/` のみ、ログに個人情報を出さない、他の世帯へのアクセス禁止のテスト）は、フォルダごとのルールと重複しても CLAUDE.md に残す（`paths:` 付きのルールは、そのフォルダを扱うまで読み込まれないため）
- 安全に関わるフォルダごとのルールは `.claude/rules/` に置き、人間だけが変更する（0004）。安全に関わらない規約（UI の書き方など）は、Claude も直せるフォルダごとの CLAUDE.md に置く
- 0009 の modern-web-guidance は、CLAUDE.md・`.claude/rules/` と食い違わない範囲で参照する

## 影響

- CLAUDE.md は約 40 行になり、ADR が増えても増えない
- `.claude/rules/` の変更はひでの作業になる。振り返りで Claude が直したい場合は差分案を出す

## 見直す条件

- `paths:` 付きのルールが読み込まれずに違反が起きた
